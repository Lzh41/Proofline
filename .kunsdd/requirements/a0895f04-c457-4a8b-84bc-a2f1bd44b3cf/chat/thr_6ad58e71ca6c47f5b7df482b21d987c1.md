## 一、确认的 Bug(直接影响功能正确性)

**1. JS 样例运行 stdin 模式基本跑不通** — `src/lib/problemRunner.ts:367-372`
- `usesJavaScriptStandardInput` 认可 `process.stdin` 写法并路由到 stdin 模式,但 `codeRunner.worker.ts:27-31` 的沙箱 `new Function('input','lines','print',...)` 既不提供 `process`,又把 `input/lines/print/console` 作为同名参数注入用户代码作用域。
- 后果:用户写 `process.stdin` 的题 → `ReferenceError: process is not defined`(误导性强);stdin 模式下用户代码若声明 `const input` → `SyntaxError: Identifier already declared`。

**2. Python/JS 函数模式被 stdin 检测误伤** — `problemRunner.ts:371-372`
- `/\binput\s*\(/` 只要代码里出现一次 `input(...)`(自定义解析函数、注释示例),就跳过 harness 直接按 stdin 跑 pyodide → 解题函数从不被调用、输出为空,样例误判失败。函数模式代码里 `input.trim()` 在 JS 侧同理。**这是最常见的"样例明明对却报错"来源**。

**3. 同日重新生成计划丢失已完成记录** — `src/lib/planner.ts:85` + `useAppStore.ts:707-715`
- 每次生成返回全新计划(`completedProblemIds: []`),store 按 `item.date === plan.date` 整体替换。同一天第二次"生成计划"会清空当天已完成的题目记录。

**4. 牛客平台白名单缺 `ac.nowcoder.com`** — `src/lib/platform.ts:7`
- 牛客 ACM/练习题页面常用 `ac.nowcoder.com` 子域,`isAllowedPlatformUrl` 直接拒绝 → 绑定/导入报"不属于所选平台"。

**5. 样例期望输出引号判定不一致** — `problemRunner.ts:823-827`
- 实际输出经 `JSON.stringify`(带引号 `"hello"`),题面期望常写裸字符串 `hello` → 内容相同也判 `passed: false`。

## 二、高风险的隐患(需要并发/特定时机才触发)

**6. 恢复/清除数据无全局互斥,可致数据损坏** — `backup.rs:147-248`、`db.rs:20-40`
- 只有 `ai_request`/`platform_import` 两个锁,**没有数据库级锁**;每次命令新建 Connection。restore 流程中 `remove_file(wal/shm)` + rename 数据库期间,并发写可能丢数据或写坏文件。

**7. 远程内容驱动 panic(直接崩溃)** — `platform.rs:542`、`platform.rs:669`
- `Url::parse(&source_url).expect("validated url")`,source_url 来自 LeetCode 目录 API 和牛客页面 HTML,远程数据含非法字符 → panic;而 `Cargo.toml:48` 配置了 `panic = "abort"`(无 unwind),进程直接退出。

**8. 备份恢复 zip bomb** — `backup.rs:147-186`
- 附件解压有 10000 个/512MB 限制,但 `xiti.sqlite` 条目与 manifest.json **无大小上限**,恶意/损坏备份可写满磁盘。

**9. AI 流式响应异常路径泄漏连接** — `useAppStore.ts:395-416`
- `accept(sseDecoder.push(...))` 抛错时 `reader.cancel()` 永不执行,fetch 连接不取消也不读完,直到 GC/服务端超时。另 `:372` 新请求会无条件 abort 上一个在途 AI 请求(如流式 hint 未结束又点"连接测试")。

**10. 计时练习每秒全量写库 + 全局重渲染** — `SolvePage.tsx:432-472`
- 自动保存 effect 依赖含 `seconds`,计时中每秒触发 `updateAttempt` → SQLite 全量快照写入;配合 `storeAdapter.ts:143-157` 无 selector 订阅整个 store,所有页面每秒重渲染。长时间练习持续高负载。

## 四、工程改进建议

1. **CI 不构建/测试 Tauri 后端**:`ci.yml` 只跑前端测试和 build,Rust 侧(含 db.rs 单元测试)从未在 CI 中编译。加 cargo test + tauri build。
2. **无 ESLint/Prettier**:只有 `tsc -b` 兜底,加 lint 并接入 CI。
3. **测试盲区**:`problemRunner.ts` 1150 行中核心执行入口 `runProblemSample`(worker 调度/超时/聚合)完全未测——而最严重的 bug #1/#2 正在这个区域;`db.rs` 的 21+ 个 Tauri 命令无任何集成测试;`buildInterviewPrompt`/`parseInterviewExaminerResponse` 仅靠 e2e 覆盖。
4. **SQLite 并发**:每次命令新建连接 + 5s busy_timeout,写-写并发直接报 `database is locked`。建议单连接 + 写队列或 WAL 模式复用。
5. **FTS5 中文分词**:默认 unicode61 tokenizer 把中文整句当单 token,句中间查询词搜不到,可用 jieba 或 trigram tokenizer。
6. **代码卫生**:`db.rs:578` 动态拼接 SQL(现为硬编码常量,非注入,但属异味);`platform.rs:513` 用户输入可达路径的 `unreachable!()`。

## 五、新功能建议(按性价比排序)

1. **历史提交记录/版本回溯** — 基于现有备份机制,自动留存每日快照,支持时间线回滚(数据丢失类 bug #3/#6 的天然兜底)。
2. **错题间隔复习提醒(Anki 式)** — 已有 Mistakes 页面和计划系统,可按遗忘曲线(1/3/7/15 天)自动排期复习,在 Today 页聚合"今日待复习"。
3. **样例运行新增 C++/JS 断点调试或逐步执行可视化** — 目前只有运行结果弹窗,对算法学习场景,"逐步执行+变量状态"是最高价值功能。
4. **AI 解题过程的本地缓存/离线队列** — AI 回答目前离开页面即中断且不缓存;可把 AI 请求转为可重试队列,结果本地持久化,弱网/断网也能恢复。
5. **知识图谱关联** — Knowledge 页与错题/题目已有关联数据,可生成"薄弱知识点 → 相关题目"的拓扑图,一键跳转刷题。
