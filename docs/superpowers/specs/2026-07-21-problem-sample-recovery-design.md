# Proofline 题目样例恢复设计

## 目标

让力扣、LeetCode、牛客、手动录入、普通链接和 OCR 题都能保存并运行结构化样例；已有题目的正文中若包含样例，应能本地补齐，无需删除题目重新导入。

## 数据流

1. 平台绑定或强制刷新时，由 Rust 连接器读取公开题面，不携带 Cookie。
2. 连接器优先解析平台公开结构，再用统一的“输入/输出/解释”文本解析器兜底。
3. 前端收到平台结果后，对样例规范化、去重并写入 `Problem.examples`；SQLite 同步到 `samples` 表。
4. 已有题目在运行前若没有结构化样例，先从本地 `Problem.content` 提取，不需要联网。
5. 用户可在做题页打开样例编辑器，新增、修改或删除样例；保存后立即参与本地运行。

## 平台策略

- 力扣中国与 LeetCode：保留 GraphQL 的 `translatedContent/content`、`sampleTestCase` 和代码模板读取；解析 `<pre>` 样例，并兼容正文标签变化。
- 牛客：从公开 HTML、嵌入 JSON 的题面字段以及页面正文中识别样例；首个样例输入同时作为 `sampleTestCase`。
- 手动、普通链接与 OCR：不依赖平台连接器，使用本地正文解析和样例编辑器。

## 交互

- 题目顶部增加“补齐样例”命令。平台题会强制刷新公开数据；其他题从本地正文提取。
- 样例区域增加“编辑样例”命令，打开紧凑对话框；每条样例包含输入、预期输出和可选解释。
- 点击“运行样例”而题目没有样例时，先尝试本地补齐；仍为空则打开样例编辑器，并给出明确提示。
- 刷新失败不覆盖已有题面、代码模板或样例。

## 边界与错误处理

- 输入和输出必须同时非空才是可自动判定的样例。
- 同输入、同输出的样例合并；保留用户已有样例优先级。
- 最多保留 20 条样例，每个字段限制 20 KB，防止异常页面放大本地数据。
- 链表、树等复杂参数可以保存，但运行器无法生成入口时继续显示现有的明确错误，允许用户调整样例格式。
- 强制刷新只访问当前题的公开 URL，并沿用现有 5 秒超时与域名校验。

## 验收

- 当前正式库的四道旧力扣题能从本地正文补出样例并写入 SQLite。
- 新绑定的力扣题保留公开样例、`sampleTestCase` 和代码模板。
- 牛客 HTML/嵌入 JSON fixture 能解析结构化样例。
- 手动题可新增、编辑、删除样例，刷新失败不丢数据。
- 做题页无重叠、无页面级滚动条回归，深浅主题均可用。
