# Proofline 企业面试题工作台设计

## 目标

在现有 Proofline 桌面应用中增加独立的“面试题”工作台，让用户可以按岗位检索并练习技术八股文、场景题、系统设计题和项目追问，同时复用现有的计时、AI、错题、复习、知识库、每日计划、导入导出和备份能力。

首版必须满足以下结果：

- 内置不少于 360 道可离线使用的原创整理题，不使用空壳标题或占位答案。
- 每道内置题至少包含题面、岗位、知识分类、题型、难度、标签、参考要点、完整参考答案和一条追问。
- 覆盖传统研发岗位和当前 AI 岗位，支持按岗位名称和别名检索。
- 算法题与面试题在界面和统计上分开，在计划、错题和知识沉淀上形成统一学习闭环。
- 旧算法题、旧数据库和旧备份升级后保持可用。

## 非目标

- 首版不抓取或镜像招聘网站、面经网站和企业内部题库。
- 内置题不标记为任何企业的官方真题，不暗示企业背书。
- 首版不自动更新题库；题库随应用版本更新，设置页显示内容版本。
- 首版不为口述回答做本地语音识别。用户使用文本整理回答，后续可扩展录音或转写。
- 面试题不进入 Monaco，不调用代码运行器，也不要求编写测试函数。

首版岗位筛选包含：

- 大语言模型应用开发

- AI 平台 / MLOps 工程师
- 推荐与搜索算法工程师
- 后端开发工程师

- 数据工程师

岗位使用规范名称和别名表。搜索“LLM、大模型、语言模型”都能匹配大语言模型应用；搜索“自然语言处理”能匹配 NLP；搜索“智能体”能匹配 Agent。岗位表是可扩展常量，不把岗位写死在页面组件中。

## 信息架构

### 导航

在“题库”之后新增“面试题”主导航，使用 Lucide `BriefcaseBusiness` 图标。新增路由：

- `/interviews`：面试题工作台。
- `/interviews/:id`：面试练习页。

全局搜索继续默认搜索算法题；进入面试题页面后提供针对面试题的独立搜索框，避免改变现有快捷键行为。

### 面试题工作台

页面由四个稳定区域组成：

1. 标题区：显示题库内容版本，提供“随机一题”和“新增题目”。
2. 岗位横向筛选：传统岗位和 AI 岗位同级展示，窄屏可横向滚动但隐藏滚动条。
3. 过滤区：关键词、知识分类、题型和掌握状态。
4. 主区：左侧问题列表，右侧今日面试训练摘要。

列表列为“问题、岗位、题型、状态、操作”。问题行显示不超过三个标签，长标题使用省略显示并保留完整标题提示。空状态提供“新增第一道面试题”和“恢复内置题库”两个明确动作。

### 面试练习页

桌面端使用固定高度工作区，避免页面级滚动条：

- 顶部：题面、岗位、题型、标签、计时和结束练习。
- 左侧：用户回答编辑区，自动保存草稿。
- 右侧：AI 模拟面试官或离线参考区。

用户提交回答前不直接显示完整答案。提交后可以依次执行：

- 查看参考要点。
- 继续追问。
- 点评回答。
- 指出遗漏。
- 生成改进稿。
- 查看完整参考答案。

无 AI 凭据时，“继续追问、点评回答、指出遗漏、生成改进稿”显示禁用原因；参考要点、完整答案、计时、草稿、复盘和复习保持可用。

练习结束时必须记录掌握度“掌握、模糊、不会”，并可填写遗漏点与改进回答。模糊和不会自动进入复习队列，掌握可以直接完成当日任务。

### 响应式与主题

- 使用现有 Proofline 深浅主题变量，不新增独立品牌色。
- 1440×900 和 1280×720 使用左右练习布局。
- 768px 以下改为题面、回答、教练上下排列。
- 390px 下保留全部核心操作，按钮允许换行，不能产生横向页面溢出。
- 页面级滚动条隐藏；列表和长答案允许内部滚动并隐藏可见滚动条，滚轮、触控板和键盘仍可滚动。
- 补全悬停、焦点、按下、禁用、加载、空数据、错误和内容溢出状态。

## 数据模型

为最快复用完整学习闭环，面试题扩展现有 `Problem`、`Attempt`、`Mistake` 和 `DailyPlan`，但在 UI、运行器和统计层显式区分类型。

### Problem

`Problem` 增加：

```ts
type ProblemKind = 'algorithm' | 'interview';

interface InterviewProblemData {
  catalogId?: string;
  catalogVersion?: number;
  contentOrigin: 'builtin' | 'user' | 'import' | 'ai';
  primaryRole: string;
  roles: string[];
  category: string;
  format: 'knowledge' | 'scenario' | 'system-design' | 'project';
  keyPoints: string[];
  referenceAnswer: string;
  followUps: string[];
  archived?: boolean;
}
```

`Problem.kind` 为必填字段。旧数据规范化时默认 `algorithm`。`Problem.interview` 只在 `kind === 'interview'` 时存在。内置题沿用数据库允许的 `manual` source，在 UI 中根据 `contentOrigin` 显示“内置题库”，避免重建 source 约束和误报来源。

内置题的 `externalId` 使用 `interview:<catalogId>`，保证导入与升级稳定去重。题库更新可以覆盖内置题正文，但不能覆盖用户的练习、错题、知识笔记和归档状态。

### Attempt

`Attempt` 增加：

```ts
type AttemptMode = 'code' | 'interview';

interface InterviewAttemptData {
  answerText: string;
  aiFeedback?: string;
  omissions?: string;
  improvedAnswer?: string;
  masteryResult?: 'mastered' | 'uncertain' | 'unknown';
}
```

旧尝试默认 `mode: 'code'`。面试尝试不读取 `code`，但为兼容数据库将其保存为空字符串。成功结果判断集中到统一 helper，算法题成功为 `sample-passed/accepted`，面试题成功为 `mastered`。

### Mistake 与复习

继续复用 `Mistake.problemId`，新增面试错因分类：

- `incomplete`：关键点遗漏。
- `unclear`：表达不清。
- `no-example`：没有结合实例或项目。

复习间隔沿用 `1/3/7/14/30` 天：

- “不会”创建或重置错题，下一次复习为 1 天后。
- “模糊”创建错题，下一次复习为 1 天后。
- 复习成功按阶段推进。
- 复习失败重置到 1 天。
- 达到最后阶段后标记掌握。

### DailyPlan 与统计

`DailyPlan` 增加 `targetAlgorithmProblems` 和 `targetInterviewQuestions`，任务 ID 仍统一保存在 `taskProblemIds`。计划顺序为：到期复习、薄弱岗位面试题、薄弱算法标签、其他新题。

统计层提供两个互不污染的视图：

- 算法统计：保留现有通过数、难度分布和算法标签。
- 面试统计：练习数、掌握数、平均掌握度、薄弱岗位、薄弱知识分类和到期复习数。

## 内置题库更新

内置题库放在独立、可测试的数据模块中，不在页面 JSX 中写死。每次应用启动时只执行一次版本检查：

1. 数据库无 catalog 版本时，插入完整内置题库。
2. catalog 版本增加时，按稳定 `catalogId` 新增或更新内置题。
3. 用户自己创建和导入的题目不参与 catalog 覆盖。
4. 用户练习记录、错题、计划完成情况和知识关联不随题目更新删除。
5. 用户归档的内置题更新后保持归档。

设置页显示题库版本、内置题数量和“恢复内置题库”命令。恢复操作只恢复缺失或损坏的内置题，不删除个人题目和学习记录。

## 新增与批量导入

“新增题目”对话框包含题目、主岗位、其他岗位、分类、题型、难度、标签、参考要点、完整答案和追问。必填字段缺失时阻止保存，并把焦点移到第一个错误字段。

批量导入支持 JSON：

- 先校验所有记录，再显示新增、更新、跳过和错误数量。
- 自定义题目按显式 ID 或 `kind + title + primaryRole` 去重。
- 面试题和同名算法题不能互相合并。
- 导入失败不写入半成品数据。

## AI 面试官

AI 继续使用现有 OpenAI 兼容接口、Windows 凭据库、隐私确认、流式响应、60 秒超时和取消机制。

新增面试意图：

- `interview-follow-up`
- `interview-critique`
- `interview-omissions`
- `interview-improve`

提示词必须包含题面、岗位、参考要点、用户回答和已发生的追问；不能伪造用户没有说过的内容。AI 生成内容保存到现有 `AiGeneration`，并关联面试题与当前尝试。

## SQLite、备份与兼容

快照 schema 升级为 2，`normalizeSnapshot` 继续接受 schema 1：

- 旧 `Problem.kind` 默认 `algorithm`。
- 旧 `Attempt.mode` 默认 `code`。
- 旧设置补齐面试计划默认值和 catalog 版本。

新增幂等迁移 `002_interview_workbench.sql`：

- `problems.kind`，默认 `algorithm`。
- `problems.interview_json`，默认 `{}`。
- `attempts.mode`，默认 `code`。
- `attempts.interview_json`，默认 `{}`。
- `daily_plans.target_algorithm_problems`。
- `daily_plans.target_interview_questions`。

Rust 迁移器改为顺序执行全部迁移，并保持事务回滚。结构化表同步必须读写新增列，同时修复 `daily_plan_tasks` 把复习任务误写为 `new` 的现有问题。

桌面备份仍打包整个 SQLite 数据库，格式不变；清单增加算法题、面试题和面试练习计数。AI 密钥与平台 Cookie 继续排除。旧备份恢复后自动执行 schema 2 迁移。

## 错误处理

- 内置题库校验失败时不写入任何 catalog 更新，保留现有题库并显示明确错误。
- 题库为空时允许恢复内置题库或新增个人题目。
- AI 不可用时仅禁用 AI 命令，不影响离线题库、参考答案和复习。
- 草稿保存失败时保留编辑器内容，显示重试动作，不能静默丢失回答。
- 导入中的非法岗位或题型逐条报告，不使用未知值悄悄替换。
- catalog 更新、导入和备份恢复都必须在事务或完整快照验证后提交。

## 测试

### 单元测试

- 内置题库不少于 360 道，ID 唯一，全部必填内容非空。
- 每个岗位达到最低覆盖量，题型比例符合设计。
- 岗位别名搜索、全文关键词和掌握状态筛选正确。
- schema 1 快照默认补齐算法类型，旧数据不丢失。
- 同名算法题和面试题不会错误去重。
- 内置题升级保留练习记录、错题和归档状态。
- 面试题“掌握、模糊、不会”分别产生正确计划与复习结果。
- 算法统计不包含面试练习，面试统计不包含算法尝试。
- AI 面试提示词包含回答和参考要点，并支持取消。
- 备份清单包含面试实体计数。

### Rust 与集成测试

- schema 1 数据库升级到 schema 2，重复迁移幂等。
- 新字段结构化同步后重启可恢复。
- 旧备份恢复后自动迁移，面试数据往返完整。
- 迁移失败事务回滚，原数据库仍可打开。
- `daily_plan_tasks` 正确区分 `review` 与 `new`。

### 端到端测试

- 按“大语言模型应用”筛选并打开一道题。
- 输入回答、刷新页面并恢复草稿。
- 提交回答后解锁参考要点和完整答案。
- 选择“模糊”后进入错题和下一日复习。
- 无 AI 密钥时 AI 按钮禁用但离线流程完整。
- 深浅主题切换后题库和练习页均保持可读。
- 1440×900、1280×720、768×900 和 390×844 无重叠或横向页面溢出。
- 原有算法做题、运行样例和统计流程继续通过。
